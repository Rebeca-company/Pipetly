# Evaluation — LLM-Judge Benchmark for Pipetly

This directory contains the full evaluation infrastructure for Pipetly. It benchmarks the quality of extracted protocols across different LLM backends using an automated **LLM-as-a-judge** approach, powered by **Claude 5 Sonnet** via OpenRouter.

## Benchmark Dataset (`benchmark/cases.json`)

The dataset contains **5 benchmark cases**, each with:
- **`id`** – a unique identifier (e.g. `case_001`).
- **`query`** – the full user prompt given to Pipetly (includes domain context, format instructions, and the specific protocol objective).
- **`protocols`** – a dict mapping **source name → protocol text**. Sources currently in the dataset:

| Source key | Description |
|---|---|
| `gemini_pro` | Reference protocol generated by Gemini 1.5 Pro directly from the source paper |
| `bioprobench` | Ground-truth concise protocol from the BioProbBench benchmark |
| `pipetly_gemini-3-flash-preview` | Protocol extracted by Pipetly using Gemini 3 Flash Preview |
| `pipetly_deepseek-v4-flash` | Protocol extracted by Pipetly using DeepSeek v4 Flash |
| `pipetly_mimo-v2.5` | Protocol extracted by Pipetly using Xiaomi MiMo v2.5 |

Sources with empty text or a `PLACEHOLDER` marker are automatically skipped by the judge.

The benchmark cases cover a range of biomedical techniques: cell culture and encapsulation, radiometric kinase assays, CRISPR plant transformation, genome editing knockin, and macrophage immunomodulation assays.

## Evaluation Workflow

The evaluation runs in three sequential steps:

### Step 1 — Run the pipeline (`run_evaluations.py`)

Runs the full Pipetly pipeline for every **case × model** combination.

```bash
# Run from the project root (where main.py lives)
python evaluation/scripts/run_evaluations.py
```

- Iterates over all cases in `benchmark/cases.json`.
- For each case, runs the pipeline for each model by setting the `LLM_MODEL_GENERAL` environment variable.
- Saves outputs to `evaluation/runs/<case_id>_<model>/`:
  - `final_output.md` — the Markdown report generated by Pipetly.
  - All intermediate JSON files from `intermediate_outputs/`.
  - The `telemetry/` directory.
- Skips combinations that already have a completed run directory.

Models currently configured:
```
google/gemini-3-flash-preview
deepseek/deepseek-v4-flash
xiaomi/mimo-v2.5
```

### Step 2 — Sync results into the dataset (`update_protocols.py`)

After the pipeline runs are complete, sync their extracted protocol texts into `cases.json` so the judge can score them.

```bash
# Run from the project root
python evaluation/scripts/update_protocols.py
```

This script:
1. Removes any stale `pipetly_model*` placeholder keys from `cases.json`.
2. Reads each `benchmark/reference_outputs/case_XXX.md` and populates the `gemini_pro` source key.
3. For every run directory in `evaluation/runs/<case_id>_<model>/`, extracts the **`### Protocol Steps`** section from `final_output.md` and saves it under the key `pipetly_<model>` in `cases.json`.

### Step 3 — Score with the LLM judge (`llm_judge.py`)

Evaluates all protocols in `cases.json` using Claude 5 Sonnet as the judge.

```bash
# Run from the project root
python evaluation/scripts/llm_judge.py

# Or point to a custom dataset
python evaluation/scripts/llm_judge.py --data path/to/cases.json --out path/to/output_dir
```

- Runs **3 independent evaluation rounds** (N_RUNS = 3) to mitigate LLM non-determinism.
- All (entry, source) pairs are evaluated **concurrently** (up to 5 parallel calls) with exponential backoff on failure.
- Outputs are written to a timestamped directory under `evaluation/results/`:
  - `scores_raw.json` — the full structured output: all runs, all sources, all metrics.
  - `scores_summary.md` — a Markdown report with average scores per source and per-metric justifications from Run 1.

## Evaluation Metrics

Each protocol is scored on a **1–5 scale** across six quality dimensions:

| # | Metric | What it measures |
|---|---|---|
| 1 | **Relevance** | Does the protocol match the requested technique without mixing in steps from another protocol? |
| 2 | **Completeness** | Are all expected steps, reagents, equipment, and measurable parameters present? |
| 3 | **Parameter Consistency** | Are numerical values (volumes, times, concentrations, temperatures) coherent and plausible throughout? |
| 4 | **Executability** | Are instructions explicit and unambiguous enough to follow without consulting the source paper? |
| 5 | **Structural Coherence** | Do steps follow a logical, dependency-correct sequence without gaps or broken ordering? |
| 6 | **Conciseness** | Is the protocol free of noise, redundancy, and content that doesn't belong in a protocol (e.g., theory, results)? |

**Scale:**
- `1` = Very poor
- `2` = Poor
- `3` = Acceptable
- `4` = Good
- `5` = Excellent

Each score is accompanied by a brief justification (max 30 words) generated by the judge. The **mean score** is the arithmetic average across all six metrics.

> **Note:** The judge model (`anthropic/claude-5-sonnet`, temperature 0.1) has no access to the original source paper. It evaluates each protocol self-contained, using only its expert biomedical knowledge.

## Data Models (`scripts/models.py`)

| Model | Description |
|---|---|
| `MetricScore` | A single metric result: `score` (int, 1–5) + `justification` (str) |
| `JudgeResult` | Full 6-metric evaluation for one protocol. Exposes `mean_score` and `to_score_dict()` |
| `EvaluationEntry` | One benchmark case: `id`, `query`, and `protocols` dict. Exposes `active_sources` |
| `SourceResult` | Judge result for a single (entry, source, run) triplet. May contain an `error` |
| `RunResult` | All `SourceResult` objects for one complete evaluation round |
